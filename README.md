# OneCodex — прототип моста к конфигуратору 1С

Python + официальный MCP SDK. Поддерживает файловые и серверные базы через установленный `1cv8.exe`. OpenAI API и отдельный API-ключ не нужны: инструмент подключается к существующему Codex как локальный MCP-сервер.

## Что работает

- Профили подключений; основная конфигурация либо одно указанное расширение на профиль.
- Первая XML-выгрузка, последующее обновление `-update -force`.
- Проверка `/GetConfigGenerationID`: если сохранённая конфигурация не изменилась, повторная выгрузка пропускается.
- Поиск объектов по имени/синониму, чтение свойств, реквизитов, табличных частей, типов и подчинённых объектов.
- Поиск по BSL, постраничное чтение модулей, локальный черновик, сравнение с исходным текстом.
- Загрузка только выбранных BSL-модулей через `-listFile -partial` после просмотра плана.
- CF/CFE-копия конфигурации перед загрузкой; отдельная проверка конфигурации после загрузки.
- Долгие операции выполняются в фоне: `sync_sources`, `apply_changes`, `check_configuration` возвращают `job_id`, состояние читается через `get_job`.

## Установка (Windows)

Требуются Python 3.11+ и установленная платформа 1С. Клонируйте репозиторий и создайте окружение:

```powershell
git clone https://github.com/soft2k/onecodex.git
cd onecodex
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install -e .
Copy-Item connections.example.json connections.json
```

В `connections.json` укажите путь к своему `1cv8.exe` и параметры подключений. Имя профиля в следующих примерах — `file-test`; замените его на своё. Локальные подключения, кэш, черновики, копии конфигураций и журналы исключены из Git.

Из каталога `onecodex`:

```powershell
.\.venv\Scripts\python.exe -m onecodex connections
.\.venv\Scripts\python.exe -m onecodex sync file-test
.\.venv\Scripts\python.exe -m onecodex metadata file-test --text Номенклатура
.\.venv\Scripts\python.exe -m onecodex modules file-test --text Реализация
.\.venv\Scripts\python.exe -m onecodex search file-test ОбработкаПроведения
```

CLI ждёт завершения фоновой операции и выводит результат. MCP возвращает идентификатор сразу.

`requirements.lock` фиксирует проверенные версии зависимостей. Для разработки можно установить только `-e .`, чтобы разрешить зависимости из диапазонов в `pyproject.toml`.

## Подключение к Codex

Чтобы подключить сервер к Codex в VS Code или приложении, выполните из каталога проекта:

```powershell
.\.venv\Scripts\python.exe scripts\register_mcp.py
```

Скрипт добавляет сервер в пользовательский `~/.codex/config.toml`, предварительно сохраняет копию настроек и прекращает работу при конфликтующей регистрации. Перезапустите MCP-подключение или Codex, чтобы появились новые инструменты.

Для ручной настройки получите фрагмент командой:

```powershell
.\.venv\Scripts\python.exe -m onecodex codex-config
```

Добавьте выведенную таблицу `[mcp_servers.onecodex]` в пользовательский `config.toml` Codex, сохранив существующие настройки, и перезапустите подключение. Для других MCP-клиентов используйте stdio-команду и аргументы из фрагмента.

Пример запроса после подключения:

> Используй onecodex. Синхронизируй file-test, дождись get_job, найди документ реализации и прочитай его обработку проведения.

При правке: `read_module` → `stage_module` (полный новый текст и SHA256 исходника) → `review_changes` → просмотр пользователем → `apply_changes` с `plan_id` → `get_job`.

Для небольшой правки большого модуля используйте `patch_module`: точный старый и новый фрагмент, SHA256 исходника. Старый фрагмент должен встречаться ровно один раз. Команда готовит черновик от синхронизированного исходника и заменяет прежний черновик этого модуля; для нескольких правок объедините замену либо передайте полный текст через `stage_module`.

## Подключения

Мост теперь сам читает список запуска 1С (`%APPDATA%\1C\1CEStart\ibases.v8i`) и общие списки из настроек стартера. Пароли из списков не импортируются. Наличие записи в стартере не подтверждает доступность базы или права пользователя.

В чате Codex:

> Используй onecodex. Покажи все базы из списка запуска 1С.

Затем:

> Добавь выбранную тестовую базу как подключение, пользователь Admin, без пароля.

Инструменты: `discover_bases` показывает базы и предупреждения чтения; `import_base` добавляет выбранную по `base_id`, не выгружая её и не меняя существующие настройки. `list_connections` показывает и настроенные подключения, и обнаруженные базы (`configured=false`). Для уже синхронизированных подключений поле `configuration` содержит имя и версию конфигурации из последней выгрузки; для остальных эти сведения пока неизвестны.

Если базы нет в стартере, можно указать её прямо в чате:

> Добавь подключение test-server к серверной базе server1c\test_base, пользователь Developer.

Для этого предоставлен инструмент `add_connection`. Новые подключения через MCP создаются с `allow_apply=false`. Если нужна конкретная версия платформы, укажите `platform` — полный путь к её `1cv8.exe`. Версия `Version` из списка стартера сохраняется как требование: мост не запускает профиль на заведомо несовпадающей версии.

CLI:

```powershell
.\.venv\Scripts\python.exe -m onecodex discover
.\.venv\Scripts\python.exe -m onecodex import-base 'base-ID' --user Admin
```

Произвольные дополнительные файлы `.v8i` можно перечислить в массиве `discovery_lists` в `connections.json`. Веб-базы и URL общих списков пока не поддерживаются; они отражаются в предупреждениях. Произвольный поиск баз по дискам и перечисление всех баз кластеров не выполняется.

После обновления кода перезапустите MCP-сервер/расширение Codex, чтобы появились новые инструменты. Новые записи в списке запуска 1С после этого обнаруживаются при каждом запросе списка без перезапуска сервера.

`connections.example.json` содержит образцы. Пароли не записываются в JSON: используется имя переменной окружения `password_env`. Конфигуратор получает пароль через `/P`, поэтому его может видеть пользователь с доступом к списку процессов.

```powershell
.\.venv\Scripts\python.exe -m onecodex add test-server --kind server --location 'server1c\test_base' --user Developer
```

Указать `--extension ИмяРасширения`, чтобы работать с отдельным расширением. Каждый профиль имеет собственный кэш.

По умолчанию установлено `allow_apply: false`. Чтобы испытать загрузку на своей копии базы, создайте для неё профиль с `--allow-apply` либо измените эту настройку вручную и перезапустите MCP-сервер.

## Где лежат файлы

```text
state/<connection>/
  sources/          XML/BSL последней успешной синхронизации
  index.json        индекс объектов и модулей
  snapshot.json     поколение и время синхронизации
  draft/            подготовленные BSL-файлы
  baseline/         исходные тексты для просмотра разницы
  draft.json        состав текущего черновика
  plans/            планы применения
  applied/<plan>/   before.cf или before.cfe, загруженные файлы и результат
  logs/             журналы пакетного конфигуратора
  jobs/             результаты завершённых задач
```

Исходники `sources` обслуживает мост; редактируйте через `stage_module`. Черновики не перезаписываются при синхронизации. Ненужные сохранённые файлы черновиков не загружаются: загружается только состав манифеста плана.

## Ограничения первого варианта

- Работает с сохранённой основной конфигурацией конфигуратора; несохранённый текст открытого редактора не виден. Обновление конфигурации БД (`/UpdateDBCfg`) выполняйте самостоятельно в конфигураторе.
- Редактирование через мост пока ограничено существующими BSL-модулями. Создание объектов, правки XML/форм, изменение схемы данных не входят в этот прототип.
- Требуется платформа с `-partial` (проверяемая версия: 8.3.27.1859). Защищённые/непоставляемые тексты модулей платформа не раскрывает.
- Первичная выгрузка большой конфигурации остаётся долгой. Чтение после выгрузки локальное; поиск по тексту пока линейный, без семантического индекса.
- Любое изменение поколения конфигурации после подготовки черновика блокирует загрузку, даже если правка была в другом объекте. Требуется пересмотреть и заново подготовить черновик. Система не объединяет конфликты автоматически.
- Перед загрузкой сохраните свою работу и закройте другие сеансы конфигуратора этой базы. Блокировка моста предотвращает параллельные операции моста, но не блокирует внешнего разработчика. Последняя проверка поколения не является атомарной блокировкой 1С.
- Поддержка и захват в хранилище регулируются самой платформой. Мост не снимает поддержку и не захватывает объекты автоматически.
- Проверка выполняется **после** загрузки. Ошибка проверки не откатывает уже загруженные модули. CF/CFE — копия конфигурации, не резервная копия данных базы. Восстановление выполняется вручную.
- При таймауте загрузки состояние базы может быть неопределённым. Прочитайте журнал и проверьте конфигурацию перед повторением. При аварийном завершении процесса `operation.lock` может остаться; удалять его вручную следует только после проверки, что процесс завершён.
- Фоновые задачи живут в процессе MCP. Завершённые результаты сохраняются; перезапуск не возобновляет незавершённую задачу.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tests\mcp_smoke.py
```

`tests/test_core.py` использует имитацию конфигуратора для проверки конфликтов, порядка операций, резервной копии, выборочной загрузки, сохранности исходников/черновиков и путей. Реальные проверки платформы описаны в `VALIDATION.md`.
