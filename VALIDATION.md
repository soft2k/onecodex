# Результаты проверки — 11 октября 2026

Среда: Windows, Python 3.12.14 из окружения Codex, MCP SDK 1.30.0, платформа 1С 8.3.27.1859.

## Автоматические проверки

- 31 тест в `tests/test_core.py` и `tests/test_discovery.py`: все прошли.
- Реальное MCP stdio-рукопожатие: прошло; сервер публикует 17 инструментов, вызов `list_connections` успешен.
- Проверены точечная замена, сохранение BOM/CRLF, конфликты версий, запрет устаревшего плана, выборочная загрузка, резервная копия и сохранение исходного текста.

## DemoTrd — чтение

Профиль `demotrd`: файловая база, пользователь `Admin`, без пароля, `allow_apply=false`.

- Полная первоначальная XML-выгрузка и индексирование завершились: 20 843 описания объектов, 13 358 BSL-модулей. Ошибок индексирования: 0.
- Общая длительность первой операции около 11,5 минуты, включая индексацию в каталоге OneDrive. Первичная выгрузка остаётся затратной операцией.
- Повторная синхронизация заняла около 4 секунд: поколение не изменилось, выгрузка пропущена.
- Через интерфейс моста найден `Document.РеализацияТоваровУслуг`, прочитаны свойства и подчинённые объекты; найдены 9 связанных модулей, прочитан модуль объекта из 3 869 строк.
- Проверка локального черновика: `tests/verify_demo.py`; результат в `state/demo-validation.json`. Загрузка в DemoTrd не выполнялась.

## Отдельная тестовая база — запись

`tests/platform_integration.py` создал отдельную пустую файловую базу внутри `state/platform-validation`. DemoTrd в этой проверке не использовалась.

Проверен реальный цикл: загрузка начального модуля управляемого приложения → выгрузка → подготовка изменения → просмотр плана → CF-копия → частичная загрузка одного BSL-модуля → проверка конфигурации → инкрементальное обновление выгрузки → чтение изменённого текста.

Проверка платформы сообщила «Ошибок не обнаружено». Повторная синхронизация после применения пропустила выгрузку. Обновление конфигурации БД не запускалось.

Полный отчёт и путь к CF-копии: `state/platform-validation/result.json`. Тестовая база и журналы сохранены для осмотра.

## Подключение Codex

Сервер `onecodex` добавлен в пользовательский `config.toml`, прежние настройки сохранены в отдельной копии. Регистрация проверена чтением TOML. Использование новых инструментов непосредственно из этого чата требует перезапуска/переподключения MCP; до этого проверялся отдельный официальный MCP-клиент.

## Пока не проверено

Подключение к реальной серверной базе, запись в большое прикладное решение, работа с хранилищем конфигурации, расширения и восстановление из CF/CFE. Реальный тест записи охватывает модуль управляемого приложения в небольшой файловой базе. Для серверного подключения проверено формирование команды `/S`.

## Обнаружение баз

Из реального списка запуска прочитаны четыре локальные записи. Существующий `demotrd` распознан по пути, повторное подключение не создаётся. Новые реальные базы не экспортировались и не изменялись.

На временных файлах проверены локальные и общие списки, серверные строки подключения, UTF-8/UTF-16/CP1251, дубликаты, сохранение существующих параметров, добавление профилей, версия конфигурации из кэша и отсутствие паролей в результатах обнаружения. В одной записи стартера указан `Version=8.5.1`; это требование отображается пользователю и проверяется перед запуском платформы.
